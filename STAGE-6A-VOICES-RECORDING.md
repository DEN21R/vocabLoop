# Этап 6А. Выбор голоса и запись своего перевода

Продолжение [этапа 6](./STAGE-6-SPEECH.md), перед Listening Sessions из [PLAN.md](./PLAN.md).

**Один шаг → объяснение → ты пишешь → проверяем → дальше.** Файлы создаём по мере работы. Этот документ заменяет старый план с хранением аудио в браузере.

## Что получим

- Выбор браузерного голоса для каждого языка.
- Запись перевода своим голосом через микрофон.
- Сохранение одной записи внутри слова в существующей MongoDB.
- Выбор источника перевода: браузерный голос или своя запись.
- Простое управление «Слушать / Стоп». Пауза остаётся отложенной.

Используем твой существующий кластер и подключение приложения. Новый кластер и отдельный сервис хранения не нужны.

Запись доступна с другого устройства после входа в тот же аккаунт, если приложение и backend доступны этому устройству. Сейчас API использует localhost:3000; при размещении приложения адрес заменим. Для микрофона нужны localhost или HTTPS.

Аудио занимает место в текущем тарифе MongoDB. У Atlas Free общий лимит базы — 512 МБ. Ограничим одну запись 30 секундами в интерфейсе и 1 МБ на сервере.

## Часть 1. Браузерные голоса

### Шаг 1. Показать список голосов

**Где:** существующий `client/src/shared/lib/tts/speech.ts` и новый `features/play-word/ui/VoiceSettings.tsx`.

1. Получить голоса браузера: название, язык и идентификатор `voiceURI`.
2. Показать списки выбора для en, ru, de и uk. В каждом — голоса только соответствующего языка.
3. Добавить «Автоматически». Если голосов нет — показать «Нет доступного голоса».
4. Обновлять список по событию voiceschanged, снять подписку при размонтировании. Использовать существующую подготовку голосов.

**Результат:** видишь доступные варианты. На этом смотрим код и переходим дальше.

### Шаг 2. Применить и запомнить выбор

**Где:** `speech.ts`, `useWordPlayback.ts`, `HomePage.tsx`, экспорт `features/play-word/index.ts`.

1. Хранить выбор «язык → voiceURI» в состоянии страницы и передавать панели и хуку.
2. В speakText добавить необязательный идентификатор голоса. Если задан — использовать этот голос соответствующего языка.
3. «Автоматически» оставляет нынешний поиск по языку.
4. Сохранить выбор в localStorage. Если после загрузки списка голос исчез — использовать автоматический голос того же языка.
5. Во время воспроизведения выбор блокировать.

**Проверка:** выбрать голос, услышать его, обновить страницу — выбор сохранился.

Настройка голоса локальна, потому что доступные голоса зависят от устройства. Аудиозапись будет храниться на сервере.

## Часть 2. Хранение в MongoDB

### Шаг 3. Добавить поля слова

**Где:** `server/src/modules/word/Word.js`.

| Поле              | Назначение                            |
| ----------------- | ------------------------------------- |
| recordingData     | Байты аудиофайла, тип Mongoose Buffer |
| recordingMimeType | Формат, например audio/webm           |
| hasRecording      | Есть ли запись; по умолчанию false    |

Поля записи необязательные. Для recordingData установить select: false, чтобы при получении списка слов не скачивать всё аудио. Ответы создания и изменения слова также должны возвращать только нужные поля без аудиоданных. Base64 не нужен.

**Проверка:** старые слова и добавление новых работают без записи.

### Шаг 4. Сделать три маршрута

**Где:** существующие `word.routes.js` и `word.controller.js`.

| Маршрут                     | Действие                      |
| --------------------------- | ----------------------------- |
| PUT /words/:id/recording    | Сохранить или заменить запись |
| GET /words/:id/recording    | Получить аудио                |
| DELETE /words/:id/recording | Удалить запись, оставив слово |

1. Использовать существующий protect. Искать слово по ID и владельцу из токена.
2. На PUT после авторизации подключить express.raw только для загрузки аудио, с лимитом 1 МБ. Принимать непустой Buffer и согласованные аудиоформаты MediaRecorder. MIME-тип описывает формат, но сам по себе не доказывает содержимое файла.
3. Сохранять данные, формат и hasRecording: true одним обновлением. Новая запись заменяет старую.
4. В GET явно выбрать скрытое поле и вернуть байты с правильным Content-Type. Если записи нет — 404.
5. DELETE очищает данные и формат, устанавливает hasRecording: false.

При удалении всего слова встроенная запись удалится вместе с ним. Отдельная коллекция, файловая папка и библиотека загрузки не нужны.

**Проверка:** через Postman отправить короткое аудио как binary, получить обратно и удалить. Убедиться, что чужой аккаунт запись не получает — это существующее правило владельца.

## Часть 3. Запись с микрофона

### Шаг 5. Записать и прослушать черновик

**Новые файлы:**

- `features/record-word/ui/RecordWordDialog.tsx` — диалог.
- `features/record-word/model/useWordRecorder.ts` — логика записи.
- `features/record-word/index.ts` — экспорт диалога.

1. В HomePage добавить «Записать перевод» возле слова. Открывать один общий диалог для выбранного слова.
2. В диалоге показать перевод. По кнопке «Начать запись» запросить микрофон и запустить MediaRecorder.
3. По кнопке «Закончить» остановить рекордер. После последних данных и события stop собрать Blob — файл в памяти.
4. Дать прослушать его через обычный audio controls, перезаписать или отменить.
5. Использовать фактический формат рекордера. Через 30 секунд автоматически заканчивать запись.

После завершения или закрытия диалога выключать tracks микрофона, таймер и прослушивание; освобождать временные blob-URL. Если разрешение выдали после закрытия диалога, полученный поток сразу выключить. Отказ в доступе показать простым сообщением.

**Проверка:** записать фразу, услышать себя, закрыть диалог — микрофон больше не используется.

### Шаг 6. Сохранить на сервере

**Где:** `features/record-word/api/recording.ts`, диалог, `entities/word/model/types.ts`, HomePage.

1. Добавить hasRecording к IWord. Для старых слов отсутствие значения считать false.
2. Отправлять Blob напрямую в PUT через существующий Axios-клиент с его MIME-типом. Клиент уже добавляет токен.
3. После успешного ответа обновить признак записи у слова через callback страницы.
4. При ошибке оставить черновик для повторного сохранения.
5. Добавить удаление записи через DELETE. При перезаписи старая запись остаётся до успешного сохранения новой.

**Проверка:** записать → сохранить → обновить страницу. У слова осталась запись.

## Часть 4. Воспроизведение

### Шаг 7. Получить запись и выбрать источник

**Где:** `entities/word/api/recordingApi.ts`, публичный экспорт entity, HomePage.

1. У слова с записью показать выбор «Браузерный голос / Моя запись». Без записи доступен браузерный голос.
2. Получать аудио через Axios с responseType: 'blob', чтобы передавался токен авторизации.
3. Загружать файл внутри общего запуска плеера: блокировка повторного Play и Stop должны действовать и во время запроса.
4. Не передавать защищённый адрес напрямую в audio src. Полученный Blob превратить во временный URL для воспроизведения.

**Проверка:** войти в тот же аккаунт в другом браузере и прослушать запись. На целевых устройствах проверим поддержку её формата; совместимость со всеми браузерами заранее не обещаем.

### Шаг 8. Соединить оригинал и запись

**Где:** существующий `useWordPlayback.ts` и небольшой `shared/lib/audio/playAudio.ts`.

1. Оставить один общий хук, принимающий слово и источник перевода.
2. Режим TTS: оригинал → перевод выбранными голосами.
3. Режим записи: оригинал TTS → сохранённое аудио. Голос TTS для языка перевода здесь не нужен.
4. Для аудио ждать реального ended. Ошибку загрузки или запуска показать пользователю.
5. Общий Stop останавливает текущий звук и завершает ожидание. После отмены подготовки, загрузки или оригинала вторая часть не начинается.
6. При уходе со страницы останавливать звук и освобождать временный URL.
7. Пока плеер занят, не открывать запись. Пока открыт диалог записи, блокировать общий Play. Перед перезаписью остановить черновик.

**Проверка:** услышать оригинал и свой перевод, остановить посередине, запустить снова.

## FSD без дополнительных слоёв

HomePage соединяет WordCard, настройки, плеер и диалог. Features play-word и record-word не импортируют друг друга. Чтение сохранённой записи доступно через entities/word; сохранение и удаление — через feature записи. Браузерные детали звука находятся в shared. Redux и универсальный менеджер аудио не добавляем.

## Когда этап готов

- [ ] Браузерный голос выбирается, настройка запоминается.
- [ ] Свой перевод можно записать, сохранить в MongoDB, заменить и удалить.
- [ ] Запись доступна из другого браузера/устройства под тем же аккаунтом.
- [ ] Оригинал и выбранный перевод звучат по очереди; Stop работает.
- [ ] Выполнены npm run lint и npm run build в client.

Проверки выполняем один раз по мере шагов. Дополнительные сценарии разбираем при конкретной проблеме. Пауза, распознавание речи и редактирование аудио пока не входят в этап.

## Проверенные основания

- Небольшие файлы внутри документа: [MongoDB](https://www.mongodb.com/docs/manual/core/gridfs/). Документ ограничен 16 МиБ; наш лимит записи — 1 МБ.
- Поле Buffer: [Mongoose](https://mongoosejs.com/docs/schematypes.html).
- Приём бинарного файла: [express.raw](https://expressjs.com/en/5x/api/express/#express.raw).
- Бесплатный объём кластера: [MongoDB Atlas](https://www.mongodb.com/docs/atlas/manage-clusters/).
- Микрофон и запись: [getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia), [MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder).
