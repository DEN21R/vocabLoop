# Этап 6. Озвучивание оригинала и перевода

Этот материал раскрывает этап 6 из [PLAN.md](./PLAN.md). Работаем по одному небольшому шагу: объяснение → самостоятельный код → ревью → проверка. Готовой реализации здесь нет.

## Что хотим получить

Возле слова появляется кнопка «Слушать». После нажатия сначала звучит оригинал на его языке, затем перевод на языке перевода. Можно остановить воспроизведение, поставить на паузу и продолжить. Одновременно воспроизводится только одно слово.

Используем браузерный Web Speech API — SpeechSynthesis. Новый аккаунт, API-ключ и подключение Groq для озвучивания не нужны. Сервис перевода и MongoDB на этом этапе не меняем.

Голоса зависят от браузера и устройства. Наличие перевода на украинский, русский или немецкий не означает, что на устройстве доступен голос для этого языка. Некоторые голоса могут использовать сетевой сервис: работу полностью без интернета заранее не обещаем. Свойства браузерных голосов описаны в [SpeechSynthesisVoice](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice).

## Перед началом

Этап 5 уже дал сервис перевода и форму с выбором языков. Перед дальнейшими изменениями вручную добавь слово и обнови страницу: перевод должен сохраниться. Эта проверка не заменяется проверкой TypeScript.

Раздельную обработку всех ошибок Groq и создание .env.example мы договорились отложить. Запоминание языков между закрытиями диалога — отдельное улучшение формы, оно не блокирует озвучивание.

## Шаг 1. Проверить браузер и доступные голоса

### Объяснение

Начинаем с браузера, в котором ты запускаешь VocabLoop. SpeechSynthesis получает голоса через getVoices. При первом вызове список может быть пустым; при его изменении приходит событие voiceschanged. См. [SpeechSynthesis](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis) и [voiceschanged](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/voiceschanged_event).

### Задание

1. Открой приложение и инструменты разработчика.
2. Проверь наличие speechSynthesis и SpeechSynthesisUtterance в window.
3. Посмотри список getVoices: для каждой записи нужны имя и lang.
4. Если список пуст, проверь его после voiceschanged. Пока не делай вывод, что озвучивание не поддерживается.
5. Отметь доступные языки из en, ru, uk, de. Для первой проверки выбери слово, для обоих языков которого есть голоса.

### Стоп для ревью

Сообщи браузер и найденные языки голосов. Код всех следующих шагов пока не пиши. Если нужного голоса нет, разберём доступные варианты на твоём устройстве, не подменяя язык чужим голосом.

## Шаг 2. Подготовить обёртку и выбор голоса

### Идея

Компонент передаёт текст и язык. Внутри shared/lib/tts остаются SpeechSynthesisUtterance и остальные браузерные детали. Так будущий плеер сессий сможет пользоваться теми же функциями.

### Контракт обёртки

| Функция                       | Что делает                                                                                           |
| ----------------------------- | ---------------------------------------------------------------------------------------------------- |
| prepareSpeech(languages)      | Дожидается доступного списка и проверяет наличие голосов для нужных языков; при успехе Promise<void> |
| speakText({ text, language }) | Произносит одну реплику; возвращает Promise с результатом finished или cancelled                     |
| stopSpeech()                  | Останавливает текущую реплику и завершает её ожидание как cancelled                                  |
| pauseSpeech()                 | Приостанавливает текущую речь                                                                        |
| resumeSpeech()                | Продолжает текущую речь                                                                              |

Реальную ошибку озвучивания передаём как исключение. Отмена пользователем — нормальный исход, а не ошибка интерфейса.

### Задание

1. Создай speech.ts и начни только с prepareSpeech и внутреннего выбора голоса.
2. Если браузер не поддерживает API, сообщи об этом ошибкой.
3. Прочитай список голосов. Если он пуст, дождись изменения с ограничением ожидания, например 3 секунды. Это наше время ожидания списка, не длительность произнесения.
4. Подписку на событие и таймер убирай после завершения ожидания — как при успехе, так и при ошибке. После установки подписки перечитай список, чтобы не пропустить его появление.
5. Сначала ищи точное совпадение языка, затем совпадение основной части: для en подходит en-US или en-GB, для ru — ru-RU. Сравнивай без учёта регистра.
6. Если список уже загружен, но нужного языка нет, покажи понятную причину. Не выбирай просто первый голос любого языка.

### Стоп для ревью

Проверь доступный и отсутствующий язык. Объясни разницу между «список ещё загружается» и «список есть, но нужного голоса нет».

## Шаг 3. Произнести одну реплику

### Объяснение

Вызов speak добавляет реплику в очередь, но не означает, что она уже закончилась. Наш speakText должен завершить Promise по событию end. Ошибку обрабатываем через error. См. [end](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisUtterance/end_event) и [error](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisUtterance/error_event).

### Задание

1. Реализуй speakText после успешной подготовки голосов.
2. Создай новую реплику для переданного текста и выбери соответствующий голос.
3. Задай voice и lang выбранного голоса. Скорость, высоту и громкость пока оставь стандартными.
4. Подключи обработчики до запуска речи.
5. При end заверши Promise значением finished; при реальной ошибке отклони Promise.
6. Храни ссылку на активную реплику и её завершение до окончания воспроизведения.
7. После завершения освободи обработчики и ссылку. Один вызов должен завершаться только один раз.

### Проверка и стоп для ревью

Запусти короткую реплику явным нажатием кнопки в браузере. Не запускай звук при загрузке страницы или из эффекта: начальное действие должно исходить от пользователя.

Проверь, что уведомление о finished появляется после окончания речи. На этом шаге ещё не соединяем оригинал и перевод.

## Шаг 4. Добавить остановку, паузу и продолжение

### Почему остановка требует завершить ожидание

speechSynthesis.cancel останавливает речь и удаляет очередь. Но наша обёртка также должна завершить ожидающий Promise. Иначе код после await останется ждать. О поведении браузерной очереди — [cancel](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/cancel).

### Задание

1. В stopSpeech отменяй речь и явно завершай текущий вызов speakText результатом cancelled, не рассчитывая только на браузерное событие.
2. Поздние end/error отменённой реплики не должны менять новый вызов. Используй проверку, относится ли событие ещё к активной реплике.
3. Повторная остановка без активной речи должна быть безопасной.
4. Добавь pauseSpeech и resumeSpeech, используя браузерные pause и resume.
5. Пауза не завершает Promise. После продолжения ждём фактического end.
6. Перед новым запуском после остановки сбрось оставшееся состояние паузы, если браузер его сохранил.

### Стоп для ревью

Проверь остановку посреди длинной фразы, паузу, продолжение и новый запуск после остановки на паузе. Временные кнопки проверки не обязаны становиться отдельными компонентами.

Пауза и голоса могут вести себя по-разному на устройствах. Результат проверки записывай для конкретного браузера, не обещая одинаковую работу везде.

## Шаг 5. Соединить оригинал и перевод

### Идея

Создай useWordPlayback и вызови его один раз в HomePage. В нём живут активный ID слова, состояние idle/playing/paused и сообщение об ошибке. Кнопки карточек используют общие функции этого хука.

Последовательность: подготовить голоса обоих языков → произнести оригинал → дождаться finished → произнести перевод → дождаться finished → idle.

### Задание

1. Добавь функцию playWord, принимающую IWord через публичный экспорт entity.
2. При запуске сначала сделай предыдущий запуск неактуальным и останови его.
3. Подготовь голоса для sourceLanguage и targetLanguage. Если перевод озвучить нельзя, сообщи об этом до начала оригинала.
4. Передай original и sourceLanguage в speakText.
5. Только после finished произнеси translation на targetLanguage.
6. При cancelled прекрати последовательность. После Stop перевод не должен сам запускаться.
7. Для защиты от устаревших async-результатов используй номер запуска в useRef. Новый Play и Stop увеличивают его. После каждого await и в обработке ошибки проверяй актуальность номера.
8. Привяжи stop, pause и resume к состоянию хука. Если пауза попала на границу двух реплик, следующую реплику не запускай до продолжения; простой вариант — сохранить её как ожидающее действие.
9. При уходе со страницы в cleanup сделай запуск неактуальным и останови речь, не обновляя состояние после размонтирования.

Проверка номера нужна также после подготовки голосов: пользователь может нажать Stop, пока список ещё загружается. Не используй фиксированный таймер для перехода к переводу — слова имеют разную длительность.

### Стоп для ревью

Сначала покажи Play и Stop с двумя репликами. После их проверки подключи Pause/Resume. Проверь быстрое переключение между двумя словами: после запуска B перевод слова A звучать не должен.

## Шаг 6. Подключить кнопки к карточкам

### Задание

1. Создай PlayWordButton: кнопка вызывает переданное действие и имеет понятную подпись «Слушать». Для иконки нужен aria-label.
2. Экспортируй кнопку и хук через features/play-word/index.ts.
3. В HomePage рядом с каждой WordCard отобрази кнопку, вызывающую общий playWord с нужным словом.
4. Активную карточку можно обозначить текстом «Воспроизводится» или «Пауза».
5. Общие кнопки «Стоп» и «Пауза / Продолжить» размести на странице. Не создавай отдельный независимый плеер для каждой карточки.
6. Сообщение об ошибке покажи рядом с управлением. При новом запуске сбрасывай прошлую ошибку.

WordCard остаётся представлением сущности. Она не импортирует PlayWordButton. Страница собирает их в общий блок; дополнительный widget для этого не нужен.

### Стоп для ревью

Проверь управление мышью и клавиатурой. Нажатие Play у другого слова переключает воспроизведение, а не добавляет все реплики в длинную очередь.

## Шаг 7. Проверить полный сценарий

| Сценарий                            | Ожидаемый результат                                     |
| ----------------------------------- | ------------------------------------------------------- |
| Play у слова                        | Оригинал, затем перевод                                 |
| Длинный оригинал                    | Перевод ждёт фактического окончания                     |
| Разные языки слова                  | Каждая реплика использует соответствующий голос         |
| Голоса ещё загружаются              | Ограниченное ожидание, затем запуск или понятная ошибка |
| Для одного из языков нет голоса     | Понятное сообщение, без подмены языка                   |
| Stop во время оригинала             | Речь останавливается, перевод не начинается             |
| Stop во время перевода              | Речь останавливается                                    |
| Stop во время подготовки            | Позже звук сам не запускается                           |
| Повторный Play или другое слово     | Старый запуск отменяется; звучит только новый           |
| Pause и Resume                      | Продолжение текущей последовательности                  |
| Stop на паузе, затем Play           | Новое воспроизведение не остаётся на паузе              |
| Уход со страницы или выход          | Речь прекращается                                       |
| TTS недоступен или произошла ошибка | Сообщение и возможность нового запуска                  |

Звук проверяй вручную: успешный TypeScript не доказывает, что выбран правильный язык и действительно слышна речь. После реализации выполни npm run lint и npm run build из client.
