How to build / change the component
----------------------------------
Follow UPSTREAM-BUILD.txt with Emscripten SDK 3.1.47. At each clone, check out
the corresponding revision above before continuing. The recipe includes the
local source edits, configure/CMake options, the espeak-ng-data preload and
the Emscripten command that exports createPiperPhonemize, callMain and FS.
Do not discard those edits when rebuilding. They are part of the build recipe.
Build tools are required only to rebuild the upstream component, not to use
Vocabloop or to synthesize on a phone. A bit-for-bit rebuild is not claimed.
Emscripten SDK version / source:
https://github.com/emscripten-core/emsdk/tree/3.1.47
https://github.com/emscripten-core/emscripten/tree/3.1.47

Vocabloop integration source and changes
---------------------------------------
The new Piper integration, UI and tests are available in this repository:
https://github.com/DEN21R/vocabLoop/tree/main/client/src/features/play-listening-session
https://github.com/DEN21R/vocabLoop/tree/main/client/tests
See PIPER-INTEGRATION-LICENSE.txt for the scope of its GPLv3 grant.
Changes: a separate optional test UI and Worker; the Ukrainian adapter uses
Unicode text phonemes from the unchanged uk_UA-ukrainian_tts-medium config,
instead of passing eSpeak's universal IDs to the old lada-x_low model.
The upstream WASM, eSpeak source and voice weights are unmodified.
The integration also repairs empty/interrupted OPFS cache files and uses
Worker sync OPFS access on Safari versions without createWritable().
The upstream phonemizer and inference implementation are not patched.
The temporary UI allows per-language voice selection and stores preferences
locally. Only the selected model is downloaded. Ukrainian lada/mykyta/tetiana
share unchanged weights/config and select speaker IDs 0/1/2 respectively.
Additional voice attribution and dataset terms: VOICE-SELECTION.txt.
