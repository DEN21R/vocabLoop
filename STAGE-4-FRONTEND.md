# Этап 4. Список и добавление слов на frontend

Этот материал раскрывает этап 4 из [PLAN.md](./PLAN.md). Работаем с существующим backend и домашней страницей.

Формат работы: читаешь объяснение → пишешь небольшой фрагмент → просишь ревью → проверяешь → переходишь дальше. Готовой реализации здесь нет. Создавай файлы по мере выполнения шагов.

## Что хотим получить

После входа на домашней странице загружаются свои слова. Пользователь вводит оригинал, ручной перевод и языки, сохраняет слово и сразу видит его в списке. После обновления страницы слова снова загружаются из MongoDB.

Сначала добиваемся рабочего поведения, затем можно заниматься оформлением. Используем уже установленные компоненты MUI. Автоматический перевод относится к этапу 5.

## Что уже работает и какой контракт используем

На backend есть защищённые POST и GET `/words`. Общий Axios-клиент в `shared/api/api.ts` добавляет токен из localStorage. Кнопка выхода уже находится на HomePage.

| Запрос      | Входные данные                                        | Успешный ответ                 |
| ----------- | ----------------------------------------------------- | ------------------------------ |
| GET /words  | Без тела запроса                                      | 200, объект с массивом words   |
| POST /words | original, translation, sourceLanguage, targetLanguage | 201, объект с сохранённым word |

**Используем `_id`, который уже возвращает backend.** Отдельный `id` не создаём и формат backend ради этого этапа не меняем. Это учитывает договорённость после ревью этапа 3 и заменяет первоначальное предложение переименовывать `_id` в ответе.

Слово в текущем JSON содержит `_id`, `user`, четыре текстовых поля, `createdAt`, `updatedAt`; также может приходить служебное `__v`. Для интерфейса нужны только поля, которые будем использовать. Владелец назначается сервером, в запрос создания его не отправляем.

## Как связаны файлы

Пути в таблице относительно `client/src`.

| Файл                                   | Роль                                               |
| -------------------------------------- | -------------------------------------------------- |
| `shared/api/api.ts`                    | Существующий Axios-клиент с токеном                |
| `entities/word/model/types.ts`         | Тип Word                                           |
| `entities/word/api/wordApi.ts`         | Запрос списка getWords                             |
| `entities/word/ui/WordCard.tsx`        | Отображение одного слова                           |
| `entities/word/index.ts`               | Публичные экспорты типа, запроса и карточки        |
| `features/add-word/api/addWord.ts`     | Типы и запрос создания слова                       |
| `features/add-word/ui/AddWordForm.tsx` | Поля формы, отправка, сообщение об ошибке          |
| `features/add-word/index.ts`           | Публичный экспорт формы                            |
| `pages/home/ui/HomePage.tsx`           | Хранение списка, загрузка, сборка формы и карточек |

Страница использует feature и entity через их `index.ts`. Форма может импортировать тип Word из entity, а HTTP-функции используют shared/api. Entity не импортирует feature или страницу.

Состояние списка живёт в HomePage, состояние полей — в форме. Redux, новый widget и дополнительные библиотеки для этого не нужны.

## Шаг 1. Описать тип слова

### Идея

Тип TypeScript описывает данные, с которыми работает frontend. Он не создаёт документ в базе и не проверяет автоматически ответ сервера во время выполнения.

### Задание

1. Создай `entities/word/model/types.ts`.
2. Опиши и экспортируй тип или интерфейс Word.
3. Добавь поля `_id`, `original`, `translation`, `sourceLanguage`, `targetLanguage`, `createdAt`, `updatedAt`.
4. Для этих полей используй строки: даты приходят по HTTP как строки, а не как объекты Date.
5. Экспортируй тип через `entities/word/index.ts`.

Поля `user` и `__v` для текущего интерфейса не нужны. Их наличие в реальном ответе не мешает описать только используемую часть объекта.

### Стоп для ревью

Покажи тип и экспорт. Объясни, почему поле называется `_id` и почему даты описаны строками.

## Шаг 2. Добавить запрос списка

### Идея

HTTP-функция получает данные. Она не отображает сообщения, не меняет React-состояние и не управляет переходами.

### Задание в entities/word/api/wordApi.ts

1. Импортируй общий `api` и тип Word из соседнего файла типов.
2. Опиши ответ GET: объект с полем `words` типа `Word[]`.
3. Создай асинхронную функцию `getWords` без аргументов.
4. Выполни GET на `/words` и верни `response.data`.
5. Экспортируй функцию через `entities/word/index.ts`.

Не передавай ID пользователя: backend получает его из токена. Не добавляй ещё один перехватчик или заголовок Authorization — это уже делает общий клиент. Ошибку запроса оставь вызывающему коду, чтобы он отличал сбой от пустого списка.

### Стоп для ревью

Покажи функцию и тип ответа. Проверь понимание: результат getWords — объект, а сам массив находится в его поле `words`.

## Шаг 3. Загрузить список на HomePage

### Идея

Пустой список и неудачная загрузка — разные состояния. Пока запрос выполняется, пользователь должен видеть ожидание.

Для небольшого экрана достаточно списка `Word[]` и состояния загрузки со значениями `loading`, `success`, `error`. Начальное значение — `loading`.

### Задание

1. В HomePage добавь состояние списка, начальное значение — пустой массив.
2. Добавь состояние загрузки.
3. В useEffect объяви асинхронную функцию загрузки и вызови её. Сам callback эффекта не делай async.
4. При успехе запиши `result.words` в список и установи `success`.
5. При ошибке установи `error`.
6. Добавь локальный признак отмены в эффекте и его изменение в cleanup. Перед обновлением состояния после запроса проверяй этот признак.
7. Во время загрузки покажи «Загружаем слова…», при ошибке — «Не удалось загрузить слова».
8. Сообщение «Пока нет слов» показывай только после успешной загрузки пустого массива.

На этом шаге для проверки успешной загрузки достаточно временно показать количество слов. Карточки добавим отдельно. Кнопку выхода сохрани доступной.

Сетевая ошибка не означает, что список пуст или токен недействителен. Не удаляй токен при любой ошибке загрузки. Повтор загрузки отдельной кнопкой пока не добавляем: для этой проверки достаточно обновить страницу.

В разработке StrictMode может вызвать два GET при открытии страницы. Как и в ProtectedRoute, очистка эффекта не даёт устаревшему результату изменить состояние. Это не повод переносить загрузку прямо в рендер.

### Проверка и стоп для ревью

Войди, открой домашнюю страницу и сравни количество с ответом GET в Network. Обнови страницу. Для проверки сбоя списка можно временно заблокировать именно запрос `/words` в DevTools и обновить страницу: `/auth/me` должен оставаться доступным, иначе ошибку раньше покажет ProtectedRoute.

Покажи эффект и состояния до добавления карточек.

## Шаг 4. Показать карточки слов

### Идея

WordCard получает одно слово через props и отображает его. Загрузка данных остаётся на странице.

### Задание

1. Создай `entities/word/ui/WordCard.tsx`.
2. Опиши prop `word` с типом Word.
3. Покажи оригинал, перевод и пару языков. Для начала хватит простого блока или MUI Card.
4. Экспортируй карточку через публичный `index.ts` entity.
5. В HomePage пройдись по массиву методом map и отобрази WordCard для каждого элемента.
6. В качестве React key используй `word._id`.

Порядок уже задаётся backend: новые слова первыми. Дополнительная сортировка на frontend сейчас не требуется.

### Стоп для ревью

Проверь, что несколько слов дают несколько карточек, оригинал соответствует переводу, а в консоли нет предупреждения об отсутствующем key.

## Шаг 5. Добавить запрос создания

### Задание в features/add-word/api/addWord.ts

1. Опиши тип входа: четыре строковых поля `original`, `translation`, `sourceLanguage`, `targetLanguage`.
2. Опиши ответ: объект с полем `word` типа Word. Импортируй Word через публичный API entity.
3. Создай асинхронную функцию `addWord`, принимающую входные данные.
4. Выполни POST на `/words` через общий `api`.
5. Верни `response.data`.

`_id`, `user` и даты не отправляем. Они появляются на сервере. Не скрывай ошибку запроса возвратом пустого объекта — форму нужно очистить только после подтверждённого успеха.

### Стоп для ревью

Покажи только HTTP-функцию и типы. Сравни четыре поля запроса с уже проверенным запросом из Postman.

## Шаг 6. Создать форму

### Что хранит форма

Форма хранит четыре введённых значения, сообщение об ошибке и признак отправки `isSubmitting`. Это её локальное состояние.

### Задание в AddWordForm.tsx

1. Создай форму с управляемыми полями оригинала, перевода, языка оригинала и языка перевода.
2. Для языков пока достаточно текстовых полей с начальными значениями `en` и `uk`. Список языков провайдера появится на следующем этапе.
3. Добавь кнопку отправки и обработчик onSubmit. Отмени стандартную перезагрузку страницы через preventDefault.
4. Перед запросом убери пробелы по краям значений и проверь, что они не пустые.
5. Если проверка не прошла, покажи сообщение и не отправляй POST.
6. Перед отправкой сбрось прошлую ошибку, установи `isSubmitting` и вызови addWord.
7. Пока запрос выполняется, заблокируй кнопку и поля формы. Так не получится повторно отправить слово или потерять новые правки во время ожидания.
8. При ошибке покажи «Не удалось добавить слово» и сохрани введённые значения.
9. В finally заверши состояние отправки.
10. Экспортируй форму через `features/add-word/index.ts`.

Валидация frontend помогает пользователю, но серверную проверку не заменяет. Для сообщения о сбое сейчас достаточно одного понятного текста; разбор всех видов ошибок отдельно не нужен.

### Стоп для ревью

Сначала покажи поля, проверки и обработчик. Очистку формы и добавление результата в список подключим следующим маленьким шагом.

## Шаг 7. Связать форму со списком

### Идея

Список хранится на странице, поэтому форма сообщает ей об успехе через prop-функцию `onCreated`. Эта функция получает созданное слово типа Word.

Цепочка: отправка формы → POST успешно завершён → ответ с word → вызов onCreated → обновление списка на странице.

### Задание

1. Добавь форме prop `onCreated`, принимающий Word и ничего не возвращающий.
2. После успешного POST вызови его с `result.word`.
3. Только после успеха очисти оригинал и перевод. Выбранные языки оставь — ими удобно пользоваться для следующего слова.
4. В HomePage создай обработчик: добавь полученное слово в начало текущего массива через функциональное обновление состояния.
5. Не изменяй существующий массив через push или unshift — сформируй новый массив.
6. Подключи форму на странице и передай обработчик через onCreated.
7. Показывай форму после успешной начальной загрузки списка, включая пустой список. Так поздний ответ начального GET не перезапишет только что добавленное слово.

Повторный GET после каждого добавления пока не нужен: POST уже вернул сохранённый документ с `_id` и датами. Обновление страницы для отображения нового слова тоже не требуется.

### Проверка и стоп для ревью

Добавь слово и проверь, что оно появилось первым, оригинал и перевод очистились, языки сохранились. Затем при уже открытой форме останови backend и попробуй добавить другое слово: ошибка должна быть видна, а ввод должен сохраниться. После проверки запусти backend снова.

## Итоговая проверка

| Сценарий                             | Ожидаемое поведение                                 |
| ------------------------------------ | --------------------------------------------------- |
| Открытие домашней страницы           | Ожидание, затем список своих слов                   |
| Успешный GET без слов                | Сообщение «Пока нет слов» и доступная форма         |
| Сбой GET /words                      | Сообщение об ошибке, а не о пустом списке           |
| Успешное добавление                  | Одно новое слово появляется первым без перезагрузки |
| Пробелы вокруг текста                | Отправляются очищенные значения                     |
| Пустое поле или строка из пробелов   | Сообщение в форме; POST не отправляется             |
| Запрос добавления выполняется        | Поля и кнопка временно заблокированы                |
| Ошибка POST                          | Список не изменяется, введённые данные сохраняются  |
| POST успешен                         | Оригинал и перевод очищаются, языки сохраняются     |
| Обновление страницы после добавления | Сохранённое слово приходит через GET                |
| Выход и вход другим аккаунтом        | Загружается список другого пользователя             |

После реализации запусти из папки `client` команды `npm run lint` и `npm run build`. Успешная сборка проверяет в том числе типы, а поведение подтверждаем сценариями выше.
